# Agent Note: recoverable Mobile account deletion

Status: proposed

[English](2026-09-09-mobile-account-deletion.md) | 中文

## Problem

Mobile 通过 GitHub 登录创建持久 Platform Account，但只提供当前安装退出与所选 Personal Pairing 撤销。这两个操作都不删除账号或关联个人记录。[Issue #636](https://github.com/gestaltrun/deepseek-harness-gestalt/issues/636)负责交付。

## Proposal

在现有 Account 能力和 Mobile 账户页增加账号删除。用户确认且通过 Installation proof 的请求会持久标记账号正在删除，并撤销全部 Account Session。正在删除的账号不能刷新、完成挂起登录、创建配对或恢复访问。普通退出保持[账号决策](../../implemented/feature/2026-08-17-platform-account-installation-sessions.zh.md)中的既有语义，该决策继续有效；本提案增加独立操作。

Account provider 负责小型持久删除记录及重启恢复。现有配对、路由、附件和成员关系 owner 删除该账号的权限与个人引用。保留共享项目及其他成员记录，绝不删除 Desktop 本地工作文件或 GitHub 账号。持久撤销先于连接失效通知；通知失败不能恢复授权。持久保留未完成清理，只有全部必需 owner 完成后才报告完成。不引入通用任务服务。

请求保持幂等。发送前，Mobile 保存操作标识及绑定 Installation 的恢复材料；响应不确定或重启后查询同一操作，不创建另一个操作。恢复授权只能查询删除进度及为该操作重选继任者，不能执行普通账号操作。保留恢复材料直到观察到终态，再与该账号本地会话、配对密钥和缓存一起删除。保留其他账号材料。服务端恢复记录具有配置中声明的有限运行保留期，不虚构法定保留要求。删除完成后重新注册会创建不带旧权限的新 Account id。

共享项目保留其他成员的数据。删除账号是唯一 owner 且存在其他已加入成员时，确认页必须为每个项目明确选择继任成员。删除操作持久保存 `{projectId, successorMembershipId}`；待处理邀请不是候选。成员关系 owner 校验继任者是同项目中另一位已加入成员，先将其提升为 owner，再移除删除账号的成员记录；中断后即使存在两个 owner 也能安全恢复。已有另一位 owner 时直接移除删除账号的成员记录。没有其他成员时，删除云端项目、成员、邀请、名称和 remote 索引，不触碰本地文件。继任者并发离开会使同一操作要求用户处理：回执允许重新选择继任者，已接受的会话和配对撤销持续有效。账号删除绝不能使项目失去全部 owner。

## Frozen UI and experience route

布局、字体和控件沿用现有账户页。[状态草图](2026-09-09-mobile-account-deletion.svg)冻结以下交互；它是规划示意，不是产品验收证据。

| 状态 | 内容 | 操作与结果 |
| --- | --- | --- |
| 入口 | 退出登录下方的删除账号 | 打开确认，不发请求 |
| 确认 | 全部安装与配对失去访问；本地文件和 GitHub 保留；从已加入成员中选择必需继任者 | 取消原样返回；有效选择后允许删除账号 |
| 进行中 | 正在删除账号；重新打开后继续未完成工作 | 禁止普通账号操作，保留恢复材料 |
| 完成 | 账号已删除 | 擦除该账号本地材料，返回登录 |
| 恢复失败 | 无法确认状态，或选定继任者已离开 | 重试同一操作或通过其回执重选已加入成员；不恢复访问 |

使用两个已登录安装、两组配对和一个共享项目，走真实 Mobile 账户页。先取消并验证访问保留。再确认，验证两个安装都失去访问，中断连接并重启 Mobile/Platform，重试查询进度并观察完成。为唯一持有的共享项目选择继任者；验证所有权转移、其他成员数据与本地文件保留。再次执行并让继任者在删除中离开，通过同一回执重选，验证撤销持续有效。重新注册，证明旧 token 和配对仍不可用。仅在实现候选上录制最终 GUI 路径和 GIF。

## Alternatives considered

**将退出或解除配对改名为删除。** 这两个操作保留账号和独立授权。

**跨全部存储使用一个事务。** PostgreSQL、对象存储和成员关系持久存储不共享原子提交。持久化 owner 清理使部分失败可恢复。

**要求客服删除。** 用户必须能在应用内发起真实删除流程；单独联系链接不提供持久结果。

## Acceptance criteria

聚焦测试覆盖取消、重复请求、响应丢失、重启恢复、跨账号拒绝、并发登录/刷新、跨实例撤销和清理失败，包括继任者离开与提升后中断。真实组合的无密钥产品快照覆盖 UI 状态。必需的 owner 记录与附件能力在完成前消失；属于他人的共享项目数据保留。Mobile 无需已撤销的 Account Session 即可恢复已接受的删除。新注册绝不继承已删除权限。

## Risks

身份删除必须关闭活跃 Relay 访问及登录会话。共享成员关系和保留的加密附件需要各自 owner 清理。发布政策承诺前须确认生产保留事实。Platform 与 Mobile 需要后续发布；本工作不改当前 Desktop 0.1.17 和 Android build 8 发布线。Apple 登录、provider 关联及审核专用访问绕过不属于本提案。
