# Agent Note: Composer 文本与图片批示

Status: proposed

[English](2026-08-17-composer-text-and-image-annotations.md) | 中文

## 问题

Web Composer 无法将一条已完成 assistant 回复中的精确文字或图片上的一个位置转成聚焦的用户提示词。人们必须手工引用文本或含糊地描述图片位置，丢失了文本批示先例的直接操作和 Gestalt 中已观察到的图片 pin 交互。

外部文本插件不适合作为运行时依赖：它修改已渲染的 DOM，在输入状态机之外拦截 Enter，仅在浏览器内存中保存待发送批示，并通过解析和隐藏协议文本重建呈现。Gestalt 的图片 pin 流程会向模型提供原图和百分比坐标，但其结构化 pin 在成功回显路径中会丢失。引入任一实现都会保留宿主耦合和不完整的持久化。

## 提案

批示仅作为 `@deepseek-ai/dsh-client-ui-conversation` 内由 Composer 拥有的输入状态。它不是服务、能力包、Cordis 插件、Session 事件、消息来源或内容块。提交会把草稿编译成普通用户消息；提交后，运行时中没有任何值会把该消息识别为批示消息。

### 草稿与目标

- 每个 Session 拥有一份客户端持久化的 Annotation Draft。在当前浏览器配置文件中，文本、锚点、顺序、批语、历史图片引用、已暂存图片字节和 pin 能经过 Session 切换与页面刷新保留；各标签页不实时同步，最后一个持久化写入者胜出。
- 文本批示选取一条已完成 assistant 回复中可见的文本。它可以跨越该回复内已渲染的 Markdown 范围，但不能跨越另一条消息、图片、推理行或工具卡。草稿保留精确引文和上下文，而不是 DOM 范围。
- 图片 pin 可以指向当前 Composer 图片，或同一 Session 历史中可见的持久图片。历史图片通过其现有的内容寻址引用重新附加。坐标相对已显示且应用 EXIF 方向的光栅归一化；动态 GIF 仍可发送，但不能添加 pin。
- 批语可以为空。文本和图片的批示顺序都是创建顺序；删除项目会重新计算展示编号，但不会改变草稿身份。只有草稿存在时，文本高亮和图片 pin 才保持可见且可编辑；成功提交或丢弃后它们会消失。

### 提交

- Annotation Draft 可以在没有单独问题文本时提交；编译后的消息会请模型处理被批示的位置。
- 编译器输出普通的本地化自然语言段落；有单独问题文本时先放问题，再按顺序放入引文、图片身份、百分比坐标和批语。它不输出结构标签、隐藏标记、回答格式指令或模型回复编号要求，也没有客户端会在之后把该消息反解析为批示。
- 图片 pin 会发送原图和百分比坐标文本，而不是烧录了标记的派生光栅图。历史来源图片会再次包含在已提交消息中，因此压缩或上下文选择不会只留下无源的坐标引用。
- 批示不增加数量、引文、批语或总字节限制，也绝不截断内容。当所选模型声明上下文容量时，提交会预检组装后的请求，并在溢出时保留草稿且拒绝发送；未声明容量时，实际的模型提供方溢出仍作为可见失败。
- 问题文本、图片和编译后的批示文本组成一次提交尝试。Composer 可以乐观清空，但任何拒绝都会恢复完全相同的文本、顺序、锚点、已暂存图片和 pin；成功提交会释放草稿状态。

### 呈现与落点

- 已提交消息使用现有用户气泡，并完整显示自然语言问题和批示，不使用 chip、折叠、高度上限、逐条复制、来源跳转或批示操作。现有复制操作会复制完整消息。自动标题优先使用开头的问题；没有问题时使用第一条批示文本。
- fork 只继承种子中已有的普通文本和图片消息。它不继承批示对象或来源装饰，因为提交后这些内容不存在。
- 文本选取、草稿装饰、图片编辑器、序列化和持久化模块位于 `client-ui-conversation` 内，并通过类型化内部接口扩展其输入状态机、Markdown 渲染器和图片查看器。它们不扫描或重写已渲染消息，不注册全局 Enter 拦截，也不修改 `agent-loop`。
- Web Session Surface 通过其现有 `client-ui-conversation` 组合获得该功能，DeepSeek Gestalt 则从 Web Host 继承它。Mobile Companion 编辑不在本提案范围内。
- 外部文本插件既不安装也不注册，其仓库也不进入 `vendor/`。实现把它的用户路径和 Gestalt 的点编辑器行为作为先例，同时针对当前 TypeScript 和 React 所有者重写。任何实质性源码移植都保留外部 MIT 声明和锁定的源修订。

## 已考虑的备选方案

**将外部仓库放入 `vendor/`。**已拒绝，因为 `vendor/` 拥有锁定的 Cordis 基础，而该功能是产品 UI，其外部实现依赖私有 DOM 结构且没有测试。

**将外部仓库安装为内置插件。**已拒绝，因为其捕获监听器与 Composer 输入状态机竞争，其发送失败处理可能丢失待发送批示，呈现还依赖解析和删除消息 DOM。

**创建 Annotation 服务、包、事件或内容块。**已拒绝，因为批示仅在提交前需要结构化身份。普通的已编译用户消息已经能重建模型的精确输入，而持久批示词汇会为产品在发送后丢弃的行为引入 Session、SDK、压缩、提供方和兼容性工作。

**解析已提交自然语言以恢复批示。**已拒绝，因为可解析模板会变成另一种协议标记，且无法从任意文本恢复权威的消息、Markdown 或图片来源身份。

**将 pin 烧录到派生光栅图。**已拒绝，选择了发送原图和百分比坐标，从而保留已选定的 Gestalt 交互，并避免重复或转换图片产物。

**提交后保留高亮和 pin。**已拒绝，因为永久装饰会跨轮次累积，并暗示持久批示身份。草稿标记与草稿在同一提交点消失。

## 验收标准

- 在一条已完成 assistant 回复中选择文本会打开批示编辑器，接受空或非空批语，并绘制可编辑的草稿高亮，同时不接受被排除的目标。
- Composer 图片和持久历史图片会打开点编辑器，在缩放和重新加载后保留显示方向坐标，提交时重新附加历史图片，并拒绝 GIF pin 而不阻止普通 GIF 发送。
- 混合文本和图片批示保留创建顺序，支持编辑和删除，在一个浏览器配置文件中经过 Session 切换和页面刷新后仍然存在，并在独立标签页之间按最后持久化写入者收敛。
- 仅批示和问题加批示的提交都会生成普通自然语言用户消息和原始图片块，不产生批示事件、消息元数据、内容块、隐藏标记或回复格式要求。
- 被拒绝的提交会恢复完全相同的 Annotation Draft；成功提交会移除每个草稿高亮和 pin，并仅留下普通用户消息。
- 历史、复制、标题回退、恢复和 fork 都使用普通消息行为，且绝不把已提交文本反解析为批示。
- 聚焦的单元测试和客户端集成测试覆盖锚定、坐标、排序、持久化、序列化、失败恢复和排除规则；真实 Web 组合快照覆盖模型可见消息。
- 浏览器验收覆盖文本与图片创建、重新加载恢复、历史图片重新提交、发送清理，以及容量已知时的模型提供方溢出；用户可见变更包含从真实 Web 流程录制的 GIF。

## 风险

- 已提交消息无法提供逐条批示的来源跳转、编辑、删除、分组或结构化导出。重新引入任何这类行为都需要新的持久数据决策，而不是解析旧消息。
- 对视觉模型而言，百分比坐标文本可能不如可见光栅标记可靠，尤其是图片内容密集或提供方对方向的解释不同时。
- 当模型容量在调度前未知时，无上限的批示内容可能超出上下文；产品会报告该模型提供方失败，但不会截断或自动重试。
- 浏览器本地草稿持久化不会在标签页、浏览器、设备或 Mobile Companion 之间实时同步，最后写入持久化的操作可以替换另一标签页中未发送的草稿。
- 将该功能保留在 `client-ui-conversation` 内，是有意用独立组合与卸载能力换取一个一致的输入状态机，并避免新增运行时词汇。
