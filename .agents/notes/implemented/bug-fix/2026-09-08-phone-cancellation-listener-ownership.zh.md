# Agent Note: 手机取消与监听器所有权

Status: implemented

[English](2026-09-08-phone-cancellation-listener-ownership.md) | 中文

## Problem

手机运行时启动暂停会在每轮探测后保留调用方、代际生命周期、就绪窗口和子进程退出监听器。池占用的等待器完成或拒绝后也会保留调用方中止监听器。这些监听器会在正常的就绪重试和重复获取中持续累积。

phone-stream HTTP 所有者为每个已准入事务提供取消信号，但会话与设备清单读取以及受管 Agent 读取与安装并未全部接收该信号。因此 Host 关停只能等待这些后端操作自行结束。三个 ui-phone 可观察源还允许一个抛错的渲染器订阅者阻止后续订阅者，并让异常逸出到刷新或连接工作中。

## Decision

一个启动作用域的 `AbortController` 把子进程退出投影到每次就绪暂停。暂停在就绪窗口、代际生命周期、调用方和子进程退出信号上安装同一个完成回调；任意完成路径都会清除定时器并移除全部四个监听器。池占用会在等待器完成或拒绝前立即移除调用方中止监听器。

每个 phone-stream 会话、Agent 和设备清单后端调用都接收其所属 `PhoneHttpTransactions` 的信号。受管 Agent 安装在选项中携带同一信号。清单、清单驱动的环境源和连接可观察对象逐个隔离订阅者异常，通过可注入报告器报告，默认写入控制台诊断，并继续当前派发。

## Alternatives considered

**依赖一次性中止监听器。** 拒绝：`{ once: true }` 只在对应信号中止时移除监听器。成功的暂停和占用会让长期存活的调用方与代际信号保持未中止状态。

**只在后端完成后检查 closing 标志。** 拒绝：该检查能阻止延迟响应提交，却无法中断关停正在等待汇合的操作。

**让订阅者异常拒绝刷新。** 拒绝：渲染器失效通知是观察回调。一个损坏的观察者不能回滚已经提交的快照，也不能阻止其他已挂载视图收到快照。

## Consequences

就绪重试和已完成的占用不再遗留其拥有的中止监听器。phone-stream 关停会主动取消全部已准入的后端调用，再等待它们汇合。ui-phone 订阅者失败会产生一条诊断，其余订阅者仍能收到已提交状态。

运行时池仍只拥有 Host 的外部代际。Host 终止后的原生进程登记不属于本决策。
