# Agent Note: 详情占用方声明自身宽度范围

Status: implemented

[English](2026-08-18-details-occupant-width-ranges.md) | 中文

## 问题

三栏 AppFrame 对所有占用方统一使用 300/360/520px 详情范围。该几何适合普通工具详情，但页面型占用方无法扩展到足够实用的宽度。提高全局最大值会改变既有工具详情行为；绕过布局解析器则可能让详情栏挤占 Session Surface 的必要空间。

## 决策

`ctx.layout.openDetails(range?)` 接受 `DetailsWidthRange`，其中包含正数像素宽度 `minimum`、`default` 和 `maximum`，且三者按从小到大排列。省略范围时，系统解析为普通详情的 300/360/520px。切换到不同范围会采用其默认宽度；再次打开具有相同三个值且已经打开的范围时，则保留拖动后的偏好。关闭操作写入零；下次打开恢复所请求范围的默认值。

根布局 store 将当前范围与瞬时详情宽度一并保存。拖动写入按该范围夹取，纯让步解析器也使用其中的最小值和最大值。解析器仍为 Session Surface 保留 640px 最小宽度：先将详情栏收缩到占用方最小值；两栏仍无法容纳时，再把渲染宽度推导为零。自动关闭不会改写偏好宽度，因此窗口变宽后会恢复该宽度。

布局服务不保存占用方身份。范围值就是完整的几何声明：两个调用方请求相同范围时会共享当前打开宽度偏好；需要全新几何的调用方应声明不同范围，或先关闭再重开。因此 Browser Dock 可以把最大宽度设为 960px，而不会扩大普通详情。

## 验证

布局服务测试固定了范围通过公共 `ctx.layout` 接口转发的行为。store 与 AppFrame 测试以 420/640/960px 占用方覆盖打开、拖动夹取、重复打开、关闭后重开、让步、自动关闭和宽窗口恢复。解析器测试在动态范围的精确阈值处固定 Session Surface 最小宽度；不传范围的普通测试继续固定 300/360/520px 行为。当前已组装产品中还没有自定义范围占用方，因此现有无密钥浏览器详情生命周期场景保持不变；Browser Dock 将提供首个已组装的自定义范围。

## 考虑过的替代方案

**把全局详情最大宽度提高到 960px。** 不予采纳，因为所有既有占用方都会获得新的拖动几何，而只有页面型内容需要该宽度。

**为 Browser Dock 增设独立网格或覆盖层。** 不予采纳，因为第二条布局路径会重复实现拖动、让步、Session Surface 保护和自动关闭行为。

**把宽度元数据附加到 `details` slot 声明。** 不予采纳，因为 slot 声明标识渲染位置，而 `openDetails` 标识当前查看意图。范围选择继续留在既有控制接口上，便于一个声明式布局 store 统一拥有状态转换与几何。

**按占用方身份持久化各自宽度。** 不予采纳，因为面板几何仍是瞬时状态，布局服务也不应了解产品专属的占用方 id。按范围值比较即可保留当前拖动宽度，无需增加身份注册表。

## 后果

详情占用方可以请求与其内容匹配的几何，布局所有者则继续只维护一套拖动与让步实现。普通详情保留既有宽度。自定义占用方每次打开时都必须传入其范围；省略范围会明确选择普通几何。系统依照文档中的顺序规则信任同进程插件输入，解析器继续通过推导关闭详情栏，而不是改写存储的偏好。
