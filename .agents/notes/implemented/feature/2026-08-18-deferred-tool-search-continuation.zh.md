# Agent Note: 延迟工具搜索是持久发现

Status: implemented

[English](2026-08-18-deferred-tool-search-continuation.md) | 中文

## 问题

每次模型请求都发送全部具有资格的工具 schema，会让请求成本随完整 catalog 一起增长。省略体积较大或很少使用的 schema 需要一种延续机制：模型找到相关定义后，下一个请求必须包含它；恢复 Session 时，还必须从事件日志重建该决定。发现操作不得削弱既有的实时资格规则；这些规则已经决定 agent 可以查看和执行哪些已注册工具。

## 决策

已注册的 `ToolDefinition` 可以声明 `deferLoading: true`。它仍可通过宿主 catalog 查看，但请求组装与生成的 Code Mode 绑定会省略它，直到持久化的 Session 事件日志包含一条成功工具结果，且其中的 `discoveredTools` 包含同名项。当实时的具有资格的视图中至少有一个延迟定义时，注册表会贡献保留的 `tool_search` 传输。其确定性有界搜索只在该视图上运行，并把匹配的 `ToolSchema` 值作为普通工具结果内容和结构化 `discoveredTools` 字段返回。

发现是已记录状态，不是注册表激活操作。结果会保留模型实际看到的 schema，而之后每个请求都会从当前注册表视图重新加载名称。因此，即使旧结果已经发现某个定义，该定义一旦被移除、遮蔽、限制或取消资格，仍会消失；直接执行也继续使用同一套实时仅允许权限。搜索传输本身属于呈现基础设施，只要存在具有资格的延迟候选项就保持可用。

`ToolResultBlock.discoveredTools` 是提供方无关的持久表示。agent loop 会把成功执行中的发现复制到已记录结果。pi-ai 适配器将其名称映射为 `addedToolNames`，使提供方原生的客户端工具搜索历史能够标记同一个发现点。Code Mode 会把嵌套调用中的发现转发到外层成功结果，并根据请求可见的定义集合重新生成绑定。

## 验证

工具注册表测试固定延迟省略、确定性有界搜索、不改变注册表、保留名称处理，以及最后一个延迟注册 dispose 后的行为。循环重建测试固定搜索 → 延续 → 调用，并证明发现后撤销仅允许资格会移除 schema 且阻止执行。LLM 消息与 pi-ai 上下文测试固定持久冻结和原生延续元数据，适配器测试则捕获真实锁定依赖生成的 Responses 请求。无密钥 Loader 快照会启动已组装的 headless 应用，并记录初始仅含搜索的请求、持久化的已发现 schema、延续请求、工具调用、结果和最终重建请求。

## 考虑过的替代方案

**搜索返回工具时激活注册表条目。** 不予采纳，因为搜索回答的是 schema 发现问题；改变注册或资格会让历史模型行为改变当前执行权限。

**只持久化已发现名称。** 不予采纳，因为工具结果必须保留返回给模型的可加载 schema，而且提供方原生延续需要把这些名称与下一请求提供的 schema 关联起来。之后的组装仍使用当前定义，不会信任已存副本来执行。

**仅依赖提供方原生搜索工具。** 不予采纳，因为 Session 重建、非原生提供方和 Code Mode 都需要统一的提供方无关历史表示。适配器可以转换该表示，但不持有注册表状态。

**一次搜索后永久移除延迟 schema。** 不予采纳，因为后续步骤可能搜索另一项能力，而且有界结果不表示具有资格的延迟 catalog 已经穷尽。

## 后果

组合可以延迟高成本 schema，同时不对宿主发现隐藏它们。只有持久历史发现某个定义时，请求才会增长，且每次延续仍可重建。搜索结果会按返回 schema 的体积增加日志字节数，而 `maxToolSearchResults` 会限制单次调用。重命名或撤回定义会有意使旧发现失效；模型必须重新搜索当前 catalog。压缩可以遮蔽结果中的模型可见内容，但仅追加事件仍是已加载名称的权威来源。
