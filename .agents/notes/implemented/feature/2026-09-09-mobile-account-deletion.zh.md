# Agent Note: 可恢复的 Mobile 账号删除

Status: implemented

[English](2026-09-09-mobile-account-deletion.md) | 中文

首次生产切换使用显式 Platform Deploy 模式，保留现有发布候选、Environment、OIDC 和云助手检查。稳定私有记录绑定候选、批准源、有序实例与有限阶段；主机私有记录还绑定前驱容器代际、重启策略和运行配置摘要。两台文件写入方均停止后才能捕获或导入。源变化或第二份源非空会拒绝执行，不会随意选择数据。导入后的 PostgreSQL 文档采用 text 存储，因此在任何 Platform 启动前，独立源标记和当前 UTF-8 字节均匹配批准源。PostgreSQL 写入方一旦可能运行，恢复就保留该权威，绝不还原初始文件快照。全局维护截止时间也约束中断运行；超时或不匹配的事务保持可检查状态，不自动回滚到文件。

Docker 客户端超时不会停止 daemon 拥有的 CLI。因此维护命令在启动前保留专用容器身份，确认退出后才销毁；未完成的清理阻止后续操作。SQL 期限在事务内设置，并在每条语句（包括提交）前从绝对截止时间刷新，避免受阻导入在操作预算耗尽后继续写入。重入会在任何首次导入前核验两份实时文件源；PostgreSQL 一旦可能执行，失败就保留该权威，不复活旧文件写入方。

## 问题

退出当前安装和撤销选中的个人配对仍会保留持久化 Platform Account 及关联个人记录。账号删除还跨越 PostgreSQL、附件对象存储、共享成员权威及安装本地存储，这些系统的失败无法纳入同一个原子提交。[Issue #636](https://github.com/gestaltrun/deepseek-harness-gestalt/issues/636)负责此功能。

## 决策

账号删除是独立的 Account 操作。接受事务将账号标记为正在删除并撤销全部 Account Session。提供方随后先撤销持久配对和 Relay 权威，再发布会话失效通知并清理各 owner 的数据。正在删除的账号无法完成待登录流程、刷新、接入连接或发布新的配对、附件及成员引用。失效通知加快关闭，但不提供持久授权。未完成清理保持 deleting 或 action-required，并在重启后重试。重试扫描隔离并报告每个账号的失败，继续其他账号，并独立清理过期的已完成凭据。全部配置的 owner 完成后才能报告完成；重新注册取得新的 Account id。普通退出登录保留[仅针对当前安装的语义](2026-08-17-platform-account-installation-sessions.zh.md)。

Mobile 在发送前持久化操作 id、随机恢复令牌、接任成员选择及发起安装的密钥。恢复必须由同一密钥签名，权限仅限查询进度或替换接任成员。服务器尚未接受操作时，客户端使用普通 Account 授权重新提交原请求；仅凭恢复凭据不能创建删除权限。已接受删除可以在 Account Session 失效后恢复。Mobile 在删除本地账号材料前持久化云端已完成检查点。该账号的密钥与缓存清理从检查点继续，无需联系服务器，即使服务器凭据已过期也不受影响；本地清理失败会保留检查点。其他账号的数据和 Installation id 保持不变，其他设备的本地文件不会被远程擦除。服务器已完成凭据有明确的运行期限，这不等同于法定保留政策。

独占所有者且仍有其他已加入成员的项目，必须明确选择该项目的接任成员。成员事务先提升接任者，再移除待删除所有者。已有其他所有者时可直接移除；没有其他成员的项目会移除云端记录及索引，不删除本地工作区文件。接任者离开时，必须通过同一签名凭据重新选择，已接受的撤销持续生效。涉及待删除账号的邀请会移除，其他成员和数据保留。

## 共享持久化与锁顺序

生产账号删除要求使用专用的 PostgreSQL Project Membership 文档。命名空间事务锁覆盖读取、角色检查、变更、roster 版本持久化及提交，也覆盖目标尚不存在的情况。文件适配器仍用于本地单写入者组合。每次操作重新加载已提交文档，持久化失败不能留下供后续读写使用的幽灵记录。roster 失效事件在同一版本持久化后才发布。这取代了[冻结的回滚记录](../../archived/bug-fix/2026-08-27-project-membership-commit-point-rollback.md)中的精确逆操作闭包与延迟版本机制，并保留原子失败、可重试和无幽灵记录保证。

owner 事务先取得文档锁，再按 Account id 排序，为新引用的 Account 行取得共享锁。登录先锁定 Account 行，再检查删除状态和创建 Session；接受删除会撤销已提交的 Session，或阻止其创建。接受删除只持有 Account 和 Session 行锁，并在进入任何 owner 前提交，从而不会反转 owner 到 Account 的锁顺序。PostgreSQL 在提交时拒绝指向已删除或正在删除账号的新引用，也包括接受删除前已经认证的请求。每个实例串行执行删除，避免跨实例 advisory lease 占满清理所需的数据库连接。

成员导入只接受经过批准的不可变快照，且目标必须尚未初始化。独立的源摘要标记使同源重复导入在后续写入后仍为空操作；启动不会自动导入。[切换流程](../../../../docs/cookbook/platform-account-deletion-cutover.zh.md)负责停止全部写入者、源协调、备份、启用以及从当前权威导出的回滚。

部署配置将成员关系后端和删除预算从受保护 Environment 显式传递到每个容器。就绪检查将所选成员关系权威与账号删除可用性绑定。普通滚动部署不能建立共享成员关系权威：它在候选启动前拒绝权威切换，因为并发的文件与 PostgreSQL 写入方会分裂项目状态，镜像回滚也可能恢复已删除引用。独立的全写入方维护流程负责源文档批准、导入与当前状态导出。

## 附件归属

发布时保留 Account 到配对的归属关系，不依赖后续是否解除配对。OSS 元数据退役，包括消费、到期与撤销，必须先提交按配对保存的对象与配额清理记录，再执行外部删除。对象删除失败或进程重启后，记录仍在，账号完成必须等待它们清空。每次发布的 PostgreSQL advisory lock 跨越上传和最终提交，退役不能丢弃仍在进行的发布。PostgreSQL 密文清理也等待发布恢复和持久化配额释放。这些记录属于现有附件 owner，不引入通用 job service。

旧代码已退役的对象可能失去 Account 归属。仅声明生命周期规则不能证明对象已删除或最晚删除时间。切换流程要求只读清单和实际生命周期证据，将未知的历史归属或到期时间保留为发布和隐私承诺阻塞。完成仅覆盖配置 owner 所保留的数据，不宣称对全部设备或历史备份进行无法证明的彻底擦除。

## 考虑过的替代方案

**将退出登录或解除配对改名为删除。** 两者都会保留账号及独立授权。

**跨所有存储执行单个事务。** 对象存储和安装存储不能共享 PostgreSQL 提交；持久化 owner 进度可以恢复，而不重新开放访问。

**多实例继续使用主机本地成员文件。** 独立缓存文档可能恢复已删除引用，即使两个写入者恰好挂载同一文件，也仍需要共享命名空间事务。

**继续依赖成员回滚逆操作闭包。** 共享持久化已要求完整重读权威文档，保留第二套逆向变更表示只会增加漂移；失败事务丢弃暂存变更，后续操作重载已提交状态。

**以客服联系替代应用内流程。** 联系入口既不提供用户自主发起删除，也不提供持久进度。

## 后果

删除保留其他成员与本地工作文件，但可能要求选择接任者、重试及运行环境切换。真实 PostgreSQL 测试固定先写入/先删除的锁顺序、共享成员导入、附件删除失败、重启恢复和进行中上传隔离。真实 Loader/TCP/P-256 测试区分接受前请求丢失与接受后响应丢失。可运行的 Account 示例固定撤销与恢复，Mobile entry 快照固定确认、接任选择及进度呈现。原生存储测试覆盖待删除账号的全部 Desktop 密钥和操作凭据，以及另一账号隔离。删除回归覆盖单成员云端项目与索引移除、共同所有者和无关账号保留、重放资源清理重试、无效凭据，以及重复索引或无所有者导入拒绝。精确候选版本的原生 GUI 验收和最终 GIF 是独立且必须完成的交付证据，keyless 测试不能替代。Apple 登录、身份关联和审核专用访问绕过不属于此功能。
