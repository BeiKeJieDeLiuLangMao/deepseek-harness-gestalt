# Agent Note：Web 文本注释草稿

Status: implemented

[English](2026-08-18-web-text-annotation.md) | 中文

## 问题

用户可以把 assistant 文案复制进 Composer 来引用它，但这会丢失批示与精确段落之间的关系。把浏览器 `Range` 保存在草稿中，只能在 Markdown 重新渲染或页面变化前保留可视选择。发送专用注释封装还会让模型可见消息与 transcript 中展示的普通用户消息不一致。

## 决策

只有已完成 assistant 的文本块可供文本选择。已定稿的 Markdown 在渲染期间，会把普通文本、行内代码、围栏代码、原样展示的 HTML 与图片登记到同一份类型化文本投影中。选择目标使用该投影生成 Text Anchor 前后文并恢复 Draft Mark；它绝不重建已渲染消息 DOM，也不对另一份经空白归一化的字符串做引文排序。两个端点都必须解析到同一个块中已登记的源文本。生成的数学公式与脚注界面被排除，跨越它们的选择会被拒绝；只要所选片段与任意图片相交，选择也会被拒绝，包括 alt 文本为空的图片。草稿存储 Text Anchor，其中包含已完成消息／块标识、精确引文，以及长度有界的前后文。DOM range 只作为页面级 CSS Highlight 聚合使用的展示值；每个已挂载目标贡献自己的 range，因此移除一个目标不会删除其他目标的 Draft Mark。

选择文本后先打开只有「添加批示」与「复制」两个操作的工具栏。「添加批示」会打开共享的锚定批示编辑器。输入法组合期间按 Enter 不执行操作，普通 Enter 与提交按钮保存，Shift+Enter 插入换行。批示可以为空。Composer 拥有注释的创建顺序、编辑、删除与「N 条注释」摘要；其具名交互区域会在 hover 或键盘 focus 时显示完整草稿内容。

提交会把当前问题与注释快照编译为本地化普通文案。问题存在时排在最前，随后是按序编号的注释，其中包含精确引文与可选批示。Host 经既有消息 sink 接收这段文案，因此持久 `user/message`、模型请求与 user 气泡保持一致。一项由对象身份标识的 reservation 会拥有已提交的注释 id，直到 Host 接纳完成结算。在此期间，Composer 保持只读，重复提交与注释编辑会被拒绝；陈旧的结算不能影响后续 reservation，成功只移除该 reservation 拥有的注释，失败则释放同一批草稿以供重试。Host 接纳成功前，Draft Mark 与摘要保持不变；发送失败时恢复原问题，而不是编译后的文案。

未发送的注释草稿仍是常驻 Composer 状态。它们不增加 Session event，也不引入浏览器持久化格式。草稿持久化保持为独立关注点，而每条成功准入的模型可见消息都会写入日志。

## 考虑过的替代方案

**把 DOM range 保留为锚点。** Range 是 renderer 对象，Markdown remount 会使其身份失效。它适合临时高亮，不适合作为草稿含义。

**发送结构化注释元数据。** 当前模型需要的是可读上下文，而不是新协议。结构化封装会增加解析义务，也会让普通 transcript 展示不完整。

**把草稿持久化到 Session 日志。** 未发送的浏览器草稿尚不是 Session 历史。记录它们会引入超出文本注释机制的恢复与同步语义。

## 验证

聚焦组件测试覆盖 renderer 投影中的重复引文前后文、键盘跨 Markdown span 选择、行内与围栏代码、原样展示的 HTML、排除生成的数学公式、拒绝包含空 alt 图片的选择、相邻有效选择、工具栏内容、Safari 输入法结算、编译顺序、防止重复提交、拒绝在途编辑、拥有者限定的成功与失败结算、接纳后清理，以及跨目标 Draft Mark 聚合。GUI suite 覆盖会话与 Composer 锁定表层。

一个无密钥 assembled Web 场景以 replay 模型启动真实 server 与 Chromium，创建已完成的 Markdown 回答，跨普通与粗体节点选择文本，保存并重新打开共享编辑器、修改批示，再发送问题与注释，并固定精确的模型可见普通文案。它还验证 Composer 摘要与 Draft Mark 会在接纳后消失。

## 后果

- 注释含义无需存储 renderer 节点即可跨越 Markdown 重渲染。
- 模型与 transcript 接收同一条本地化普通用户消息，而不是平行的注释状态。
- 空批示保持有效，问题优先的顺序保持确定。
- 在拥有相应能力的草稿持久化加入前，刷新页面会丢弃未发送注释。
