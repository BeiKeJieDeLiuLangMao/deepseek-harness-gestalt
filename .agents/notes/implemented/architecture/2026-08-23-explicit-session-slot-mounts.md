# Agent Note: Explicit Session slot mounts reuse canonical conversation UI

Status: implemented

English | [中文](2026-08-23-explicit-session-slot-mounts.zh.md)

## Problem

A feature shell can keep a secondary Session visible while the application remains selected on another Session. The ordinary slot tree binds every Session-scoped component to shell selection, so rendering the secondary Session by copying transcript, header, and composer components creates a second presentation contract and misses independently registered conversation actions.

## Decision

The Slot registry prepares a declared non-root Session slot and ui-renderer exposes `mountSession()` as its framework entry. The mount resolves one explicit Session standard-props bundle through `UiSession.adapter.resolve(sessionId)` and acquires a render lease. The first lease calls the Session Controller's `openForRender()`; a provisional identity is opened again once when Host publication upgrades it, without changing `sessions.list.current`. Caller disposal or renderer teardown releases the lease after unmounting the independent React root. The existing declaration ledger, entry boundaries, stores, inject faces, and standard hook binding remain authoritative inside that tree.

Side Chat preallocates a child Session id and stages it through `ctx.sessions.stageProvisional()` as a renderer-only provisional identity with the reserved `Side: ` title before mounting the declared `conversation` slot with `{ renderMode: 'sidechat' }`. The title keeps list classifiers and subagent auto-activation from treating the draft as a delegated task, while the provisional marker keeps it outside durable descendant counts. The conversation shell resolves an `origin: 'subagent'` Session's Workspace from the nearest ancestor with direct Workspace membership, so the provisional composer inherits its parent's Workspace without changing Host Workspace state. Opening the tab creates no Host Session or Agent. The first submitted message atomically creates both under the preallocated id, captures the parent history, installs the selected model, and admits the prompt; Host publication upgrades the provisional row in place. The better-sidebar package owns only this child creation and lifecycle, with no in-tab thread switching or promotion chrome. The registered conversation views and `conversation.composer.bar` provide Chat/Trajectory tabs, transcript, actions, and InputBar. `ConversationSessionHeader` uses its Side Chat posture to omit the Session title, breadcrumb navigation, and agent-preset label while retaining a child-scoped descendant action plus Session actions. Seeded Session metadata records the captured parent prefix as the inherited cut and keeps the child descriptor as the first owned event; the `owned-suffix` admission adapter therefore hides only the parent prefix from the child transcript while durable parent-address validation still sees the descriptor. The adapter routes prompt, cancel, queue, command, catalog, and model operations through the Side Chat Agent lifecycle.

Session-scoped header contributions receive the explicit id through the standard kit. Side Chat suppresses breadcrumb navigation and static preset context; its descendant action reads the rendered child's catalog, schedules read that Session's `schedules` projection, and background jobs read `jobsBySession[sessionId]`. Selecting a descendant invokes the explicit renderer owner's `openSession` callback, which retargets the same Side Chat tab while preserving `sessions.list.current`; the tab retains the root Side Chat id as the lifecycle owner released on close. The better-sidebar terminal is not a conversation-header contribution; it remains scoped by the workbench tab's `SessionScope` and is not implicitly retargeted by an embedded conversation mount.

Model selection resolves through a discriminated Session-level route while one Host catalog supplies the provider groups. Ordinary Sessions combine a stock selection route with their durable `modelSelection` projection. Side Chat owns a feature route whose `inspect` reports its effective selection and routability: a provisional draft is inspected against the live parent, and a published thread is inspected against the child. The directory inspects on first load and reconnect, and again after each successful selection so owner normalization remains authoritative. Before first submission, Side Chat validates and retains the choice; child creation installs that choice in the new Agent scope. After publication, the same route updates the live child without calling the ordinary Session model RPC that subagent routing rejects.

## Render authority

Ordinary child rendering still uses the declaring entry's `renderSlot` prop. Explicit Session mounting requires the injected `uiRenderer` service, rejects `root` and root-scoped targets, and fails when the target declaration or renderer support is absent. This is a feature-shell composition operation, not a second slot-definition or component-import API.

## Alternatives considered

**Keep a Side Chat transcript and composer.** Rejected because it duplicates conversation rendering, input behavior, tool presentation, registered header actions, and accessibility fixes while continuously drifting from the main Session UI.

**Introduce a `ConversationSurface` wrapper.** Rejected because the declared `conversation` slot already composes `ConversationSessionHeader`, `ConversationSession`, and `conversation.composer.bar`; another wrapper would name the same assembly without owning new behavior.

**Select the Side Chat Session before rendering.** Rejected because a side conversation must remain visible without replacing the main Session selection or its workspace and workbench state.

**Add provisional children to the Host Workspace ledger.** Rejected because opening a Side Chat tab does not create Host state. Resolving the nearest owning ancestor keeps the draft usable while preserving that lifecycle rule.

## Consequences

Side Chat deletes its custom transcript mapping, polling, message rows, composer CSS, and thread-management toolbar while gaining canonical conversation views and input behavior automatically. Its compact header gives up title and breadcrumb navigation so the narrow panel starts at view selection, but the rendered child's descendant catalog, schedules, and background jobs remain available. Descendant navigation changes only the explicit mount target, so the main Session, workspace, and Side Chat tab survive the selection. A secondary mount keeps its own React-root lifecycle; while provisional, it opens no Host history window or Workspace record, and its shell must release the provisional row and mount when the tab changes or unmounts. Missing lineage, cycles, and a deleted owning Workspace resolve to the inert no-Workspace composer. Feature-owned admission remains necessary because Side Chat Agents do not use ordinary Session routes. Terminal scope remains an explicit workbench concern rather than an incidental consequence of the renderer binding.

## Verification

Session Controller tests pin provisional survival, publication, release, cold `openForRender()`, and the stock/feature model-route distinction. Conversation shell tests pin Workspace inheritance through a nested provisional subagent lineage. Conversation header tests pin compact Side Chat posture: `renderMode: 'sidechat'` omits breadcrumb navigation while header actions still receive the explicit owner. Conversation annotation tests pin SessionInput text and image-pin verbs, annotation-only submit, Markdown selection mapping, and Chat-store draft persistence without importing `@deepseek-ai/dsh-client-runtime/client`. Side Chat product tests remain on `packages/client/runtime` until #591. Component tests pin the exact `conversation` slot, child Session id, sidechat render mode, absent outer toolbar and preset label, compact header actions and tabs, local descendant retargeting with unchanged main selection, root-handle disposal, new-tab icon and label, and mount disposal. The keyless browser journey opens the authenticated shipped Web shell, submits through the provisional composer, and verifies publication, restoration, nested navigation, and close.
