# Agent Note: 官方文档预览拥有文件编辑器

Status: implemented

[English](2026-09-13-official-document-preview-editors.md) | 中文

## 问题

第二个内置文件标签页会优先于官方文档预览 fallback，并以另一套加载流程替换其有界分页、渲染器注册表、版本处理和沙箱 HTML。编辑已加载的前缀还可能覆盖尚未读取的文件尾部。

## 决策

`ui-sidebar-documentpreview` 仍是 Session 文件地址、预览加载、渲染器选择和标签页生命周期的唯一内置所有者。它声明 keyed、Session 作用域的 slot `sidebar.right.tab.document.editor`；补充包以现有文档渲染器 id 注册编辑器元数据和正文，不再注册另一个文件标签页或查看器清单。

官方所有者仅在普通行分页读取到达 EOF 后提供编辑。随后，它通过现有有界 `workspaceFiles.readAll` 端点取得逐字节准确的 UTF-8 源码，拒绝 NUL、无效 UTF-8、超出完整读取上限或与分页预览版本不同的结果，再把源码交给编辑器。写入成功后，标签页返回预览并由官方读取器从第 1 行重新开始；显示页拼接、本地草稿或猜测的版本不会成为权威源码。

脏草稿只在官方标签页记录的生命周期内保留。关闭准入属于官方文件定义，放弃脏内容前必须询问。保留的编辑器文本不写入布局或 Session 数据。

## 已考虑的替代方案

第二套分页 RPC 或 Better `fs.read` 控制器会重复现有 `workspaceFiles.read` 语义，并可能在固定字节前缀后停滞。由显示页重建编辑源码会丢失准确的行尾和末尾终止符。现有有界完整字节端点只在进入编辑时使用；超过其上限的文件仍可安全分页预览，但不能编辑。保存部分前缀会破坏未读内容，因此被拒绝。chain 编辑器 slot 引入没有意义的顺序；single 编辑器 slot 无法表达按渲染器区分的资格。

## 后果

Markdown、代码、纯文本、图片、PDF、HTML、导航、重试、EOF、版本变化和沙箱行为继续由官方预览实现处理。Better Sidebar 可以补充纯文本、Markdown 和代码编辑，但不能声明文件地址或加载预览内容。大文件仍可安全分页预览，只有读取到 EOF 后才可编辑。

## 验证

聚焦测试覆盖官方分页、重试、版本隔离、标签页 abort、编辑器元数据卸载、脏关闭准入和保存后重新读取的所有权。Host 的 `workspaceFiles.read` 真实临时文件测试继续作为 UTF-8 解码、长行、字节上限和跨页版本行为的依据。
