# 委派路由与上下文复用

[English](delegation-routing.md) | 中文

在派发或继续子 agent 前使用本 provider 无关参考。交付专用角色与安装模型优先级由[交付工作流](../../.agents/skills/orchestrate-dsh-delivery/SKILL.md)及其 references 维护。

## 判断是否委派

文件发现、状态、精确转换和小型本地检查使用确定性工具直接完成。边界清楚的独立任务在需要隔离上下文、并行、不同模型或独立审查时再委派。一个可变工作树保持单一 writer；只读调查和审查可以并行。

选择路由前，明确产物、读写范围、风险、验收证据、必要背景和独立性。子 agent 描述与 todo 内容遵循根文件的任务语言规则；该规则不限制子 agent 内部 prompt。源码与可观察检查决定验收，模型信心不决定。

## 显式选择路由

根据任务、当前用户限制、已验证输入能力和同类仓库工作的实测表现选择可用 provider 与模型。运行时支持时传入路由字段，不假定会隐式继承。区分 adapter 配置能力、官方产品声明与仓库任务证据。模型名字不能证明图片输入、工具、配额、计费、cache 行为或 benchmark 排名。

遵守被排除的路由，不做静默 fallback。从安装专用 owner 读取优先级，并核验实时 catalog，不使用静态账号数量。分别诊断配额耗尽、rate limit、认证、网络传输和代码失败。

## 复用或替换 owner

运行时提供目录时，在新建子会话前检查相关直属可继续子会话。owner 的生命周期跟随交付单元：在实现、检查、review finding、集成失败和验收修复中复用合适 owner。合并同一范围内的 finding，不为每个 ticket、错误或评论新建会话或回合。

直属子会话的证据、范围、权限与模型仍匹配且不要求独立判断时继续使用它。发送差量 brief，包含新目标、当前基线、失效事实、保留约束和完成证据。`send_message` 只安排后续 FIFO 回合；它不能重定向当前回合、切换 provider/model 或改变 cwd。

只有 host 明确支持且变更范围可确认时，才优先在安全回合边界切换同一会话的模型。否则报告限制，由协调器判断能力缺失或独立性是否需要替换；不得自动制造新会话。host 切换可能保存为全局默认值。

独立审查、无关工作、owner 不可用或系统性陈旧，或当前 owner 无法安全获得所需能力时新建子会话。记录原因、当前基线、保留证据、未关闭 finding 和下一项检查。重复失败本身不是换路由理由；保留 owner 并运行可区分假设的实验。

只有任务确实依赖父会话多个已完成回合中的决定，且精简 brief 会丢失必要背景时才 fork。fork 继承已完成对话历史，不包含当前 in-flight 回合，也不是独立审查。in-process spawn/fork child 继承 parent session cwd，不表示 worktree、进程、磁盘、凭据或 authority 隔离。

只有直属可继续子会话是后续消息目标。不得检查私人 session 存储或其他 session 日志来制造连续性。持久决策写入 specification、Context 文档和 Agent Notes。

## 监督与验收

把对运行中 writer 的反馈合并成一份带版本号的修复清单，在自然检查点送达。零散消息会排在运行中的回合后面；安全上需要立即停止时可以 interrupt，但 `interrupt_agent` 只停止当前回合、保留 descendants，并把已排队回合停放到后续 waking send。

正常运行的 writer 未产生新提交、失败或完成事件时，依赖 runtime 完成通知，或在无其他工作时进行一次有界 managed wait。在收到变化通知或报告结果后再核验 git、CI 或 child 状态，不为观察进度而轮询。

派发 brief 说明产物、可观察完成证据、当前 commit 或工作树差量、读写范围、排除项、相关来源、事实区分要求、实际检查与未解决限制。只有保留证据的价值高于陈旧上下文、纠错、排队等待与偏见成本时才复用；不得声称持久 KV cache。
