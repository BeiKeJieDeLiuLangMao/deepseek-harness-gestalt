# `@deepseek-ai/dsh-noise-channel`

English | [中文](README.zh.md)

Product Snow 0.10.0 adapter for Personal Pairing. The crate only configures Snow, drives `Noise_XKpsk3_25519_ChaChaPoly_SHA256` with prologue `dsh-mobile-companion-v1`, and evaluates results. It does not implement Noise tokens, X25519, ChaChaPoly, SHA-256, or a second handshake. Ephemeral private keys are generated by Snow and stored in challenge state so a non-sticky Platform Instance can rebuild the responder; reconstruction uses Snow's documented `fixed_ephemeral_key_for_testing_only` hook with those generated keys.

`SnowPairingHandshakeProvider` implements `PairingHandshakeProvider`. `createChallenge` returns the Desktop fingerprint and the 32-byte Desktop static public key for the invitation `spk` query. `completeChallenge` consumes Mobile message 1 and returns message 2 plus open pending state. `finishChallenge` consumes message 3 and replaces that state with the finished 32-byte handshake hash, which is the pairing key. `sealMobileRelayAuthority` wraps the Mobile Relay grant with AES-GCM under that hash.

`SnowMobileHandshakeClient` is the Mobile half: `begin` writes message 1, `acceptDesktopHandshake` writes message 3, `exportFinishMessage` supplies the `finish-challenge` HTTP body, and `openRelayAuthority` opens the sealed grant.

The committed WebAssembly module lives in `pkg/` and is also exported as `./snow-wasm`. Node loads the binary from that package path, then from a sibling `dsh_noise_channel_bg.wasm` next to a bundled listen entry. A browser consumer fetches the same `pkg/dsh_noise_channel_bg.wasm` URL. Rebuild with `node packages/platform/noise-channel/rust/build.mjs` after changing the Rust adapter and keep `pkg/` byte-identical in review.

## Model Experience

None, as handshake bytes and pairing keys never enter a model request.

#### KV Cache effect

None.

## Known Limitations and Deferred Work

- Companion application frames still use the existing development AES-GCM seal until pairing-key HKDF is wired through Desktop and Mobile Relay lifecycles.
- IK reconnect (`Noise_IK_25519_ChaChaPoly_SHA256`) is not assembled on WSS attach.
- Native hardware-backed wrapping of pairing keys at rest is not implemented.
